Agent instructions

How to call places.agent-mate.ai. The agent id is places-agent. Callers send a caller API key. Map-vendor keys stay on the server.

1. Architecture

Who calls

  • App BFFs — what2eat.food and where2play.place, server to server
  • MCP hosts — Cursor, ChatBox, and similar

What places-agent provides

  • search_restaurants, search_places, get_place_details, navigate
  • plan_itinerary
  • The same tools on HTTP and MCP

Callers must see the agent id places-agent (MCP serverInfo.name and HTTP field agent). That string is not localized.

2. Get a key

An admin issues a caller API key in this app. HTTP and MCP use the same key. Send it as:

Authorization: Bearer <caller_api_key>

A deleted or regenerated secret is rejected. The plaintext is shown only at create and regenerate.

3. HTTP

App BFFs call the HTTP API on https://places.agent-mate.ai with the caller API key. Browsers do not hold this key. Responses identify the service as places-agent.

4. MCP

MCP hosts use the same caller API key. Cursor (and similar) use Streamable HTTP at /mcp. ChatBox uses remote SSE at /sse — do not point ChatBox at /mcp.

Cursor mcp.json (remote)

{
  "mcpServers": {
    "places-agent": {
      "url": "https://places.agent-mate.ai/mcp",
      "headers": {
        "Authorization": "Bearer <caller_api_key>"
      }
    }
  }
}

ChatBox: Type Remote (http/sse), URL https://places.agent-mate.ai/sse, header Authorization=Bearer <key>.
