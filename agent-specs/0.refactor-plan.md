# Places-Agent 产品重构计划

## Context

places-agent MVP-1/2 快速交付后暴露质量问题：搜索不准、无图片、行程牵强、中英文 prompt 混杂、服务器不稳定、Admin 后台 bug、调用超时。按用户影响分级，拆为 8 个批次，每批 1–3 天可独立交付。测试跟着功能走，不设独立测试批次。

---

## 方法论：Spec → Test → Implement

每批严格遵循：

1. **更新 Specs** — [`agent-stories.md`](./agent-stories.md)
2. **更新设计** — [`agent-design.md`](./agent-design.md)
3. **更新测试** — [`agent-test-plan.md`](./agent-test-plan.md) 追加 TC-M*-* 测试矩阵
4. **TDD Red** → **Green** → **Refactor**
5. **验收** — `make quality` 全绿

## 批次 5: MVP-4b — 性能优化（目标 <15s）

> 调用经常超时。实测：Google 搜索 3-4s（Worker 中转），itinerary 12-13s。目标：搜索 <5s，行程 <15s，二次搜索 <1s。

### 性能基线 (2026-08-20)

| 操作 | 耗时 | 瓶颈 |
|------|------|------|
| AMAP 搜索 | 0.5s | — |
| Google 搜索 (Worker) | 3.9s | Worker 中转 |
| Google+AMAP 搜索 | 4.1s | Google 拖后腿 |
| plan_itinerary 2天 | 12.5s | 多次搜索串行 |

### Story A: Geocode 缓存

| 操作 | 文件 | 变更 |
|------|------|------|
| 新增 | `src/core/geocode-cache.ts` | LRU (address → {lat,lng,country}, TTL 10min, max 200) |
| 新增 | `src/core/geocode-cache.test.ts` | 3 tests |
| 修改 | `src/adapters/provider-resolver.ts` | geocodeFn 包裹缓存 |

### Story B: Itinerary 搜索并行化

| 操作 | 文件 | 变更 |
|------|------|------|
| 修改 | `src/core/itinerary-timed.ts` | 景点 + 餐厅 `Promise.all` 并行 |
| 修改 | `src/core/itinerary.ts` | 多天搜索 wave 并行 |

### Story C: 搜索结果短期缓存

| 操作 | 文件 | 变更 |
|------|------|------|
| 新增 | `src/core/search-cache.ts` | LRU (query+near → PlaceCard[], TTL 5min, max 100) |
| 新增 | `src/core/search-cache.test.ts` | 3 tests |
| 修改 | `src/core/tools.ts` | search 入口包裹缓存 |

### Story D: what2eat 调用链优化

| 操作 | 文件 | 变更 |
|------|------|------|
| 修改 | `2.what2eat/src/core/decide-run.ts` | geocode + search 去重 |

### 测试 (8 个)

geocode-cache hit/miss/TTL、search-cache hit/miss/TTL、itinerary <15s、二次搜索 <1s

### 验收

- [ ] 搜索 < 5s，itinerary 2天 < 15s，二次搜索 < 1s
- [ ] 全量测试无回归
- [ ] what2eat 端到端 E2E 正常

## 风险

| 风险 | 缓解 |
|------|------|
| Google Photos API 额外计费 | feature flag `GOOGLE_PHOTOS_ENABLED` |
| Google Worker 延迟 3-4s | geocode 缓存 + 搜索缓存 + itinerary 并行化 (MVP-4b) |
| 中国 bounding box 误判韩国 | geocode address 文本优先于坐标 (MVP-3c 已修复) |
| Prompt 组装增加 token 消耗 | 模板精简；监控 token usage |

## 验证方式

每批完成后：
1. `make quality` — typecheck + lint + test-coverage + test-e2e
2. 该批次 TC-M*-* 测试矩阵全绿
3. `npm run build` 零 error
